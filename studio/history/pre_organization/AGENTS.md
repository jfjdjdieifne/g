# Start here — documentary production

For video work in `youtube_documentary/`, do not rely on chat memory or old demos.

1. Read `youtube_documentary/START_HERE.md` first, then `engine/STYLE_GUIDE.md` and `engine/STYLE_REGISTRY.json`.
2. Read `engine/PRODUCTION_POLICY.json`, `engine/EDITORIAL_REVIEW_PROTOCOL.md`, and current `engine/HANDOFF_STATE.json` / `HANDOFF.md`. Current policies supersede conflicting historical prose.
3. Resolve the user's named style explicitly. **«وثائقي بحت» = `pure_documentary`**, the authentic-material approach praised in the completed Escobar film. It is one style, NOT the default for every future film. The other three families and their actual approval status are in the registry.
4. Before new production, create a per-film `style_contract.json`, record the actual selection instruction, and author `MATERIALS.json` / scene plans. Run `tools/style_contract.py check --project ...`. The common director and profile renderer have the same gate. Do not create a new engine for each film/style.
5. Do not promise that a registry or a test guarantees exceptional art. Inspect sources and the actual final encode, fix source mismatch, narration, rhythm, readability and superficial motion. No fake archive, decorative slideshow, or unperformed viewing/listening claims.
6. Keep narration and authored display English; conversation/internal notes may be Arabic. Preserve approved voice identity and untouched raw takes. Meaning determines pace, archive, camera, sound, typography and3D.
7. A named-style instruction is enough; do not re-ask it. No explicit style and no clear context means propose/clarify once, never silently inherit the last film. A user-liked concept is not an approved completed demonstration of a different style.
8. Save assets/output/recovery links and update the handoff. Historical rebuilds must be explicit and must not be presented as new-film approval. Large media stay outside Git with recovery receipts.

This guide concerns video work; do not modify unrelated repository projects or user files.
