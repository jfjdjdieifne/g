# Mandatory onboarding for video work

Read `START_HERE.md` → `engine/STYLE_GUIDE.md` → `engine/STYLE_REGISTRY.json` before using old demos or planning a new film. Then read production policy, material/ideas protocol, encoded-review protocol and the current handoff. This file also works when only the `youtube_documentary/` folder is shared.

«وثائقي بحت» means `pure_documentary`: the authentic-material approach the user praised in the completed Escobar film. It is ONE family, not the default for all videos. Other requested families: documentary with explanation, pure explainer, and explainer with selective archive. Do not invent approval of a finished explainer demonstration.

New films need a per-project `style_contract.json` and actual material/scene plan; run the shared `tools/style_contract.py` gate. Use common engines plus film profiles, not one engine per film/style. A gate passes declarations only; it cannot certify exceptional editing or replace actual final visual/audio review. Do not promise automatic error-free work.

English narration/authored display; Arabic conversation and internal notes. Preserve authentic sources, marks, quoted words, voice identity and raw takes. No fake archive or generated anchors; no superficial slides, empty2D, decorative keywords or shadows relabelled3D. Pure explainer forbids screen archive, not factual research. Record what was actually viewed/heard, fix foundational errors, preserve recoverable outputs, and update the handoff. No new rendering/voice generation is requested merely to save these styles.
