# مختبر الحركة الفريم-دقيق (Motion Lab) — إزالة العمى عن التحليل

> مبني 2026-10-14. الفكرة: دراسة الـ2fps بتغطي **المحتوى** (شو موجود بالصورة)، بس بتفوّت أي حركة أقصر من 0.5 ثانية
> (مسحة دخان، whip pan، دخول/خروج نص سريع، فلاش حمر، غمزة أسود). هي الأداة بتشتغل على مستوى الفريم الواحد
> وبتطلّع لكل حدث **ملف مراجعة** (Clip فيه صوت + شريط فريمات @15fps) + **قياس رقمي** لحركة الكاميرا.

الأداة: `tools/reference_motion.py` · الاختبار الذاتي: `python3 tools/reference_motion.py --selftest` → **PASS**

---

## 1) شو بتقيس (4 طبقات)

| الطبقة | التقنية | المخرَج |
|---|---|---|
| **1. الأحداث** | كشف قطع (scene score بـffmpeg) + أسود (`blackdetect`) + تجمّد (`freezedetect`) + صمت (`silencedetect`) | توقيتات **بالملي ثانية** لكل حدث، وكل حدث معه الـscore تبعو |
| **2. الحركة الرقمية** | لكل 1/8 ثانية: طاقة الحركة + إزاحة، وللـ0.5 ث: fit تقريبي (block-affine) لـ**بان (x,y) + زووم + دوران** | جدول: طاقة، إزاحة %عرض/ث، زووم %/ث، دوران °/ث + تسميات |
| **3. ملفات المراجعة** | لكل حدث: `clip .mp4` (±0.8 ث، **مع الصوت**) + `strip .jpg` @15fps مع تايم كود محروق | هاد هو «الفريم ورا فريم» للحركة |
| **4. الفيلمستريب الأساسي** | كل الفيديو @2fps بصفحات (قابل لأي fps) | تغطية كاملة للسياق |

**كيف بينقاس البان بدقة:** ترجمة كاملة (الفريم ككل) بـphase correlation + تحسين sub-pixel على شبكة DFT مضاعفة
(طريقة Guizar-Sicairos) → دقة ~0.05px. والزووم/الدوران من fit على إزاحات البلوكات (block=32) مع:
high-pass قبل المطابقة (مشان المناطق الساكنة ما تغلب الحافة المتحركة)، اختبار «حِدّة الذروة» (يرفض الحواف المستقيمة
يلي بتعطي وهم الإزاحة)، ورفض الإزاحات الكبيرة يلي بتنطوي (aliasing).

## 2) دقة القياس — موثّقة، مو مدّعاة

الاختبار الذاتي بيولّد فيديو صناعي بحركات **معلومة مسبقًا** (بان، زووم، دوران، قطع، أسود، صمت) وبيمتحن الأداة عليها:

| الاختبار (الحقيقة) | القياس | النتيجة |
|---|---|---|
| 5 قطع عند 3/6/8/12/20 ث | كلها بخطأ ≤ 0.05 ث | ✅ |
| بان يمين 31.25 %/ث | 31.47 %/ث (خطأ 0.7%) | ✅ |
| زووم +4 %/ث | 3.98 %/ث | ✅ |
| بان يسار+فوق −18.8 / −8.3 %/ث | −23.39 / −8.21 | ✅ |
| زووم −3 %/ث + دوران +6 °/ث | −2.57 / +5.88 | ✅ |
| لقطة ساكنة (ممنوع حركة وهمية) | طاقة 0.0، إزاحة 0.03 | ✅ |

**الحدّ العملي:** القياس دقيق لما الإزاحة بين عينتين ≥ **~1 بكسل** (بعرض التحليل 384px، و8 عينات/ثانية
= ~2%/ث بان و~1%/ث زووم). تحت هيك، الأداة بتكتب **اتجاه + إشارة `subtle_motion`** مع `confidence: subtle/low`
بدل رقم كذّاب. **كلمة الفصل النهائية دايمًا هي شريط الـ15fps** — العين بتشوف الحركة ولو الرقم ما لحقها.

كمان كل صف بالجدول فيه `resid` (جودة الـfit) و`pan_source: global|local` — شفافية كاملة.

## 3) الاستخدام

```bash
# مرة وحدة بعد أي reset
pip install -q --break-system-packages numpy pillow imageio-ffmpeg
# (ffmpeg يجي من imageio-ffmpeg — ما في ffmpeg نظامي بالساندبوكس)

# تحليل مرجع كامل (مثال: Vaping)
python3 tools/reference_motion.py "/home/user/build/videos/xkfctt5038w - ....mp4" \
        --video-id xkfctt5038w --out analysis/xkfctt5038w \
        --base-fps 2 --event-fps 15 --motion-hz 8 --bucket 0.5

# لقطة أول 90 ثانية فقط (المنطقة يلي فيها أكثر الحركات) — أسرع بكتير
python3 tools/reference_motion.py video.mp4 --video-id X --start 0 --end 90
```

**السرعة المقاسة** (ساندبوك، عملية وحدة بكل وقت): تحليل الحركة 1080p ≈ **4.5–6.5× الزمن الحقيقي**،
كشف القطع ≈ **17× الزمن الحقيقي**. يعني:
- Vaping (27:27) ≈ **5–7 دقايق** كشف+قياس.
- PayPal (57:36) ≈ **12–16 دقيقة** كشف+قياس (+ بناء المقاطع إذا القطع كتير).

⚠️ **قاعدة الساندبوك:** مهمة ثقيلة وحدة بكل وقت. ممنوع تشغيل هالأداة أثناء رندر أو whisper.

## 4) ترتيب المخرجات — «اسم كل فيديو» وفيه كل شي

```
analysis/<video_id>/
├── filmstrip/            p01_of_NN.jpg …        ← كل الفيديو @2fps (260×6 = صفحات، 30 ث/صفحة)
├── motion/
│   ├── MOTION_INDEX.md                          ← جدول عربي: الوقت | النوع | القياس | روابط المراجعة
│   ├── metrics_0.5s.json                        ← القياس الرقمي لكل نصف ثانية
│   ├── metrics_raw.npz                           ← إشارات خام (للرسوم/المراجعة الآلية)
│   └── events/
│       ├── e007_03m12s_hard_cut.mp4              ← Clip بالملي (±0.8 ث، مع الصوت = تسمع الـSFX)
│       └── e007_03m12s_hard_cut.jpg              ← 15fps × النافذة، مع تايم كود محروق
├── dossier.json          ← كل شي رقمي: قطع/أسود/صمت/تجمّد + القياس + تعريفات التشغيل
└── BREAKDOWN_AR.md       ← التفكيك المكتوب (يُبنى من المراجعة — إيدويًا/بالوكيل)
```

**القاعدة:** الميديا الخام الكبيرة **ما تروح للسنابشوت ولا للدرايف إلا عند الطلب**. يلي بينرفع للدرايف:
جداول + ملفات المراجعة (المقاطع الصغيرة/الصور) + الـdossier. هيك كل فيديو بيصير عندو مجلد باسمه، وفيه
**الدليل** (clip يثبت الحركة) + **القاعدة** (الجدول) — مو صور مبعثرة.

## 5) كيف بنشوف الفيديو «مثل فيديو عادي» ونتعلم كلشي — ثلاث مرات مرور

| المرور | على شو | كيف | شو بيطلع |
|---|---|---|---|
| **1. القصة (Content)** | كل الفيديو @2fps (فيلمستريب) + الـtranscript مربوط بالتينم كود | نمر على كل الصفحات، ونكتب لكل تغيير: شو صار | الخط الزمني الكامل: مشاهد، بطاقات، نصوص، انتقالات كبيرة |
| **2. الحركة (Motion)** | `MOTION_INDEX.md` + مقاطع المراجعة | لكل حدث: نفتح الـclip (نشوف + نسمع) ونقرا القياس | **القاعدة الفعلية**: نوع الانتقال، سرعة الكاميرا، مدة المسحة، إذا في SFX وشدته |
| **3. الصوت/النَفَس (Audio)** | clips + جدول الصمت/الأسود | نطابق: أسود + صمت = فاصل فصل | قوانين الإيقاع (متى الأسود، متى الصمت، علاقته بالبطاقات) |

**حلقة التعلم:** كل حدث بالجدول = قاعدة عامة بملف `DIRECTING_RULEBOOK.md` (المصدر: فيديو@توقيت + القياس).
وكل قاعدة **تنزل بعدين على شكل واحد من تلات:**
1. **قانون إخراج** (Semantics→صورة) → Rulebook.
2. **تقنية قابلة للنداء** (parameters + anti-patterns) → `engine/reference_lab/techniques.json` (T01–T14).
3. **وحدة بالمحرك** (كود/حركة فعلية بـ`docengine` أو محركات الـtools) → تُدرج معها اختبار QC.

**مهم:** ما في «إنجن جديد لكل فيديو». الإنجن ثابت، والمشهد بيتوصف بملف JSON (`scene-model`). المرجع الجديد
بيزيد **تقنيات** (rows بالـtechniques db) وقد يزيد **وحدات إضافية** — بس مو إنجن جديد.

## 8) ضمانة «ما يروح ولا لقطة ولا ثانية» — `tools/study_audit.py`

المختبر بيمسك الأحداث؛ **الأداة الثانية بتضمن إنّو ما حدا تجاوزها**. `study_audit.py` بتولّد **دفتر تغطية** (`COVERAGE.md`)
و بتفحص التفكيك، وبتفشل (exit 1) إذا في:

| الفحص | بيكشف |
|---|---|
| عدد صفحات الفيلمستريب (المتوقع/الموجود) + حجم كل صفحة | تايلز مقطوعة (زي الحادثة يلي وقفت عند 24:54) أو صفحات ناقصة |
| تغطية الزمن بصفوف التفكيك | **أي مقطع من الفيديو ما إله صف مكتوب** (فراغ زمني) |
| وقوع كل حدث جوّا صف | قطعة/أسود/صمت **ما انكتب عنها** |
| تطابق «of NN» بأسماء الصفحات مع المتوقع | تعارض بالعدد |

- بتقرا الأحداث من `motion/dossier.json` (المختبر) أو `metrics.json` (البيبايلن الأصلي) — حسب المتوفر.
- بتكتب `COVERAGE.md`: جدول كل الصفحات (من/إلى/الحجم/الحالة) + جدول الفراغات + جدول الأحداث غير المذكورة.
- فيها `--selftest` (5 حالات: سليمة PASS، فراغ، صفحة مقطوعة، صفحات ناقصة، توليد الدفتر) → **كلها PASS**.

**الاستخدام:**
```bash
python3 tools/study_audit.py --study analysis/DwTK_VT54OY --video-duration 3456 --emit-ledger
python3 tools/study_audit.py --study analysis/DwTK_VT54OY --video-duration 3456 --verify   # لازم PASS
```

**التعريف العملي:** المرجع ما ينحسب «مدروس» إلا لما `--verify` يطبع PASS — يعني كل ثانية إلها صف، وكل حدث مذكور، وكل صفحة سليمة.
(ملاحظة صدق: الأداة تثبت *التغطية المكتوبة* ما بتثبت *النظر* — بس بالبروتوكول كل صف لازم يوصف شو صار بالصورة، والفحص بيمنع أي صف فاضي أو فراغ.)
