# Connected-board explanation — concept blueprint, NOT a rendered/approved demo

Requested family: `pure_explainer` or the explanatory side of a hybrid. This is a worked reasoning example for a new agent, **not a compulsory board template**, a new historically researched fact, or proof that a renderer already supports every move.

## Question and mechanism

Explain an abstract network with a single point of failure. No real company, person, measured loss or historical event is asserted. Every node/icon/image in a pure-explainer version is authored illustration. If actual historical photos go onto the board, select a hybrid instead of claiming “no archive”.

Illustrative English VO, not generated or approved:

> “At first, every request goes through one hub. That makes the system easy to manage. But it also means one failure can stop everyone. Add a second route, and the same failure has a different result. The important change isn't the size of the network. It's the way the parts connect.”

## Scene logic — anchored world, changed understanding

| Spoken idea (phrase anchor, not fabricated word timestamps) | Image/state | Camera/attention | Text role |
|---|---|---|---|
| “every request … one hub” | Establish a sparse authored board: sources left, one central hub, recipients right. Several requests converge visibly through the hub. Keep identities/locations stable. | Wide enough to understand geography, then follow one request into the shared hub. The travel shows dependence, not a decorative tour. | `ONE HUB` attaches to the actual node when named, not a floating sentence card. |
| “easy to manage” | One control action changes the same hub and propagates consistently to recipients. | Hold or ease back to see propagation. Do not add a gratuitous camera orbit. | Usually none: the state change already explains it. |
| “one failure … everyone” | Hub stops; upstream requests queue and downstream activity ceases. Cause and consequence remain simultaneously readable. No fake explosion/SFX passed as real. | Pull out along the established axis so the common cause and multiple effects are visible together. | `SINGLE POINT OF FAILURE` only if reading time and the actual VO cue allow it. No full-paragraph subtitle. |
| “a second route” | A second connection appears in the same world. Show the same hub failure again, but requests now travel around it; state visibly differs. | Track the alternate path, then widen to compare outcomes. An intentional reset is explained as the same failure with a different topology, not repeated filler. | `SECOND ROUTE` briefly labels the changed relationship. |
| “way the parts connect” | Return to the original recognisable board framing, now with the new path and sustained recipient activity. | End on the overall causal relationship; hand off to the next question using the surviving route or node, not a generic wipe. | A single connection label if needed, otherwise none. |

Timing comes from the actual chosen narration and reading tests, **not fixed6-second slides**. Meaning can hold on a legible diagram or require several meaningful visual events within one sentence.

## Spatial/depth treatment

- Persistent world coordinates for nodes, labels and links; no screen-space drifting when the camera moves. Source objects and labels must remain associated through zooms.
- Choose2D if it explains the mechanism most clearly; choose2.5D/true3D for meaningful layering, occlusion or navigation. WorldXYZ, projection and depth order must really exist before claiming3D.
- Composition first: hierarchy, silhouette, material scale, lighting, contrast and negative space. Texture, bevels, shadows and cinematic grading cannot rescue unclear causal action or toy-like staging.
- A globe is not needed in this example. Use one only if geography/scale is part of the mechanism, not as a premium-looking detour. Do not turn abstract routing into a supposedly recorded historic shipment.
- Integrate sound at meaningful changes, below dialogue; no whoosh on every camera move. Let words, state changes and sound agree, with quiet where information needs to settle.

## Failure review before building the whole film

1. Can the viewer explain why the first configuration fails without reading paragraphs?
2. Does the second route visibly change the result, rather than simply adding another pretty line?
3. Is this one understandable connected scene, or five slides with animated transitions?
4. Are words readable on an iPhone while the camera moves? Do actual cue times agree with the VO?
5. Does the renderer really maintain anchors, occlusion and text visibility between keyframes? Inspect interpolated frames and the actual encode.
6. Are all visuals authored in a pure explainer? If authentic media enters, record why and use the appropriate hybrid.
7. Could a simpler picture explain better? Reject gratuitous3D as firmly as empty2D.
